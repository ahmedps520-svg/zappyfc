# Prompt for the Forgebase session

Copy everything below the line into the Claude session that manages Forgebase.

---

I need you to add a new project to Forgebase called **`zappyfc`**. It is the backend for my FC 27 Pro Clubs team website, a static site hosted at **https://zappyfc.online**. Players fill in an application form on the site. My friend and I review them in an admin dashboard. The frontend is already built and calls the exact API below, so please follow this contract exactly (same paths, field names, status codes and JSON shapes).

## 1. Data: `applications` table

| field | type | rules |
|---|---|---|
| `id` | string (uuid or similar) | generated by the server |
| `tiktok` | string | required. Strip a leading `@`. 2–24 chars, only `A–Z a–z 0–9 _ .`, can't end with `.` |
| `messages_open` | boolean | required, must be `true` (the applicant confirmed their TikTok DMs are on) |
| `platform` | string | one of: `PlayStation 5`, `Xbox Series X\|S`, `PC`, `Other` |
| `region` | string | one of: `Europe`, `UK & Ireland`, `North America (East)`, `North America (West)`, `South America`, `Middle East`, `Africa`, `Asia`, `Oceania`, `Not sure` |
| `skill` | integer | 1–10 (1 = absolute beginner, 10 = absolute best) |
| `reason` | string | required, trimmed, 2–140 chars ("why do you want to join") |
| `status` | string | `pending` (default) / `accepted` / `rejected` |
| `note` | string | private admin note, default `""`, max 200 chars |
| `decided_by` | string or null | display name of the admin who accepted/rejected |
| `decided_at` | ISO timestamp or null | when they did it |
| `created_at` | ISO timestamp | set by the server |

Also add an **admins** store with 2 accounts (me and my friend). Each has a `username`, a display `name`, and a **hashed** password (bcrypt or argon2, never plain text). Give me a safe way to set each password myself, such as a CLI command or a one-time setup step. Don't make me paste passwords into chat.

## 2. API (all JSON, base URL = whatever public HTTPS URL this project gets)

Errors are always `{"error": "human readable message"}` with a proper status code. The site shows that message to the user.

### Public
**`POST /api/applications`**
Body: `{ "tiktok", "messages_open", "platform", "region", "skill", "reason" }`
- `201` → `{ "id": "..." }`
- `400` → validation error (say which field is wrong)
- `409` → `{"error":"This TikTok already has an application waiting for review."}` if a **pending** application with the same tiktok exists (case-insensitive)
- `429` → rate limit: max about 5 submissions per IP per hour
- Ignore and reject any extra fields. The client can never set `status`, `note`, `decided_by` and so on.

**`POST /api/admin/login`**
Body: `{ "username", "password" }`
- `200` → `{ "token": "<random opaque token>", "name": "<admin display name>" }`
- `401` → `{"error":"Wrong username or password."}`
- Rate limit failed logins (for example 10 per IP per 15 min). Tokens expire after 30 days. Store only a hash of the token.

### Admin only (header `Authorization: Bearer <token>`, otherwise `401`)
**`GET /api/admin/applications`** → `200` with a JSON **array** of all applications (every field above), newest first.

**`PATCH /api/admin/applications/:id`**
Body: any of `{ "status": "pending"|"accepted"|"rejected", "note": "..." }`
- When status becomes `accepted` or `rejected`: set `decided_by` = the logged-in admin's name and `decided_at` = now.
- When status goes back to `pending`: set both to `null`.
- `200` → the full updated application object. `404` if the id doesn't exist.

**`DELETE /api/admin/applications/:id`** → `200` `{ "ok": true }` (`404` if not found)

## 3. CORS (required, the site is on a different origin)
Allow origins `https://zappyfc.online`, `https://www.zappyfc.online` and `http://localhost:8765` (local testing).
Methods `GET, POST, PATCH, DELETE, OPTIONS`. Headers `Content-Type, Authorization`. Answer `OPTIONS` preflights with `204`.

## 4. Must be reachable from the internet over HTTPS
The site is HTTPS, so browsers will block a plain `http://` API. If Forgebase runs on my own computer, set up a stable public HTTPS address for it, for example a Cloudflare Tunnel with a fixed hostname such as `api.zappyfc.online`. A random URL that changes on every restart won't work. Tell me clearly whether my computer has to stay on for the site to work.

## 5. When you're done, give me
1. The **API base URL** (for example `https://api.zappyfc.online`). I paste it into `js/config.js` → `API_BASE_URL` in the website repo.
2. How I and my friend set our passwords.
3. `curl` commands you ran to prove it works: submit an application, get a 409 on a duplicate, log in, list, accept, add a note, delete, and a preflight `OPTIONS` request with `Origin: https://zappyfc.online` that returns the CORS headers.

If something in this contract can't work in Forgebase, tell me what's different. The website keeps all API calls in one file (`js/api.js`), so small differences are easy to adapt.
